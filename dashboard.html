Plan4RES - deterministic seasonal storage value

Plan4RES computes seasonal storage value with Benders cuts on a deterministic mean-inflow forecast. Its SMS++ solver writes those cuts to bellmanvalues.csv.

Bellman value as a maximum of Benders cuts

\[ V_t(S)\;=\;\max_{\ell\in\mathcal{L}_t}\big\{\,b_\ell+\mathbf{a}_\ell^{\top}\mathbf{S}\,\big\} \]

The inflow enters as the deterministic seasonal mean \(\bar{Q}_t=\theta(t)\). Uncertainty is not represented, so the policy cannot hedge against dry years.

Solver fixes we contributed

Three defects blocked their sddp_solver from running: an MPI communicator constructed before MPI_Init; a missing -DUSE_MPI compile flag; and six bare-filename paths in ssv.sh. All fixed (see plan4res_fixes/FIXES_APPLIED.md). A remaining upstream issue - oneStepBackward: no linearization is available on the stock toyDataset - is reported to the maintainers.

MOSSHOOS - stochastic extension

Four coupled layers replace the deterministic assumption with a full stochastic treatment of inflow uncertainty.

WP2 - Haar wavelet decomposition

\[ x_t = A_J(t) + \sum_{j=1}^{J} D_j(t) \]

WP2 - Fourier seasonal fit

\[ \theta(t)=a_0+\sum_{k=1}^{K}\big[a_k\cos(2\pi kt)+b_k\sin(2\pi kt)\big] \]

WP3 - block-bootstrap scenario generation

WP4-A - SDDP water values

\[ Q_t(S)=\min_{u}\Big\{ C(S,q,u)+\gamma\,\mathbb{E}_q\big[Q_{t+1}(S')\big]\Big\} \]
\[ Q_{t+1}(S')\;\ge\;\max_\ell\{a_\ell+b_\ell S'\} \]

Supporting hyperplanes accumulate, so the approximation is a valid lower bound and improves monotonically (Pereira-Pinto).

WP4-B - Ito SDE for the inflow

\[ \mathrm{d}Q_t=\kappa\big(\theta(t)-Q_t\big)\mathrm{d}t+\sigma_0\sqrt{Q_t}\,\mathrm{d}W_t \]

CIR form keeps \(Q_t>0\) when the Feller condition \(2\kappa\theta\ge\sigma_0^2\) holds.

WP4-C - Hamilton-Jacobi-Bellman control

\[ -\frac{\partial V}{\partial t}=\min_{0\le u\le u_{\max}}\Big\{ C(S,Q,u) +(Q-u-\mathrm{sp})\frac{\partial V}{\partial S} +\kappa(\theta(t)-Q)\frac{\partial V}{\partial Q} +\tfrac{1}{2}\sigma^2(Q)\frac{\partial^2 V}{\partial Q^2}\Big\} \]

Randomness lives in the inflow \(Q\); storage \(S\) evolves deterministically once \((u,Q)\) are fixed. The value function has kinks in \(S\) where the release regime switches, so \(V\in H^1\) - which is exactly why a Haar wavelet basis attains the optimal \(O(M^{-1})\) rate.

Where we improve Plan4RES

1 - Inflow representation

Plan4RES single deterministic mean -> MOSSHOOS wavelet split + stochastic residual

2 - Scenario generation

Plan4RES none / i.i.d. -> MOSSHOOS block-bootstrap (b=4) + K-means, energy-score validated

3 - Water values

Plan4RES deterministic Benders cuts -> MOSSHOOS SDDP over the full scenario set

4 - Release policy

Plan4RES stage-wise LP -> MOSSHOOS continuous-time HJB feedback under CIR dynamics

5 - Uncertainty quantification

Plan4RES not reported -> MOSSHOOS VSS, storage-sensitivity curve, convergence rates

Reading the output. The Monte-Carlo count controls only the precision of the reported means - it cannot create variance that is not in the data. If the scenario spread is flat (check Scenarios: P10 ~ P50 ~ P90), then every model will cost the same no matter how many MC paths you request, because the release decision is forced rather than chosen. Raise MC paths to tighten the error bars; raise iterations to converge the water values; raise K only when the scenarios genuinely differ.

Reproduce everything
git clone https://github.com/belvinos91/mosshoos-plan4res.git
cd mosshoos-plan4res
pip install -r requirements.txt

# unit tests - verify each component
python3 src/sddp_clean.py        # monotone LB, VSS>=0, valid cuts
python3 src/sde_convergence.py   # EM ~0.5, Milstein ~1.0
python3 src/hjb_clean.py         # stable, U-shaped V, correct policy
python3 src/wavelet_galerkin.py  # O(M^-1) rate

# full pipeline
./run_all.sh --omvs data/OMVS_inflows.csv
python3 storage_sweep.py --inflow data/OMVS_inflows.csv

# this dashboard
python3 dashboard_server.py --port 8050
